# Universal Python Agent Kit

Набор skills и постоянных инструкций для AI-агентов разработки (Claude Code, Codex, Cursor, Gemini CLI и других). 
В основе - инженерная философия Роберта Мартина ([ub-mode](https://github.com/unclebob/ub-mode)), адаптированная 
для Python и для безопасной автономной работы агента.

## Быстрая установка

```bash
python3 install.py
```

Установщик скопирует комплект в `~/ai/agent-kit` и создаст симлинки для найденных агентов. Нужен только Python 3.9+, зависимостей нет.

| Задача | Команда |
|---|---|
| Посмотреть план, ничего не меняя | `python3 install.py --dry-run` |
| Другой каталог установки | `python3 install.py --prefix ~/tools/ai` |
| Подключить к проекту (навыки по его стеку) | `python3 install.py --project /path/to/project` |
| Только выбранные агенты | `python3 install.py --agents claude,codex` |
| Список навыков и агентов | `python3 install.py --list` |
| Убрать симлинки | `python3 install.py --uninstall` |

Существующие файлы не перезаписываются молча: при конфликте установщик спрашивает, что делать (перезаписать, сделать бэкап, пропустить, показать дифф, прервать). Подробности - в разделе [Установка](#установка).

## Уровни навыков

| Уровень | Когда активируется | Навыки |
|---|---|---|
| 0. User Skills | Всегда, для любой задачи, не только инженерной | Ваши навыки из `~/ai/user-skills/` (см. [ниже](#пользовательские-навыки)) |
| 1. Engineering Core | Всегда, для любой инженерной задачи и любого языка | `ub-engineering`, `ub-workflow`, `ub-quality-gates` |
| 2. Language & Engineering | По языку проекта и типу задачи | Python: `python-development`, `python-testing`, `python-debugging`, `python-code-review`, `python-refactoring`, `python-packaging`, `python-performance`, `python-security`, `python-documentation`, `python-data-engineering` |
| 3. Technology Specialists | Только если технология используется в проекте | `fastapi`, `django`, `sqlalchemy`, `postgresql`, `docker`, `ci-cd`, `machine-learning`, `observability` |

Активация обеспечивается тремя механизмами:

1. **`AGENTS.md`** подключается как постоянная инструкция. Он содержит сжатое изложение ядра и процедуру выбора навыков, поэтому принципы действуют даже у агента без механизма skills.
2. **Поле `description`** в каждом `SKILL.md` описывает, что делает навык и когда его применять. Агент читает только описания и загружает полный текст навыка по необходимости (progressive disclosure). В описаниях навыков уровня 3 прямо сказано «use only when the project uses …».
3. **Установщик** в режиме `--project` определяет язык и технологии проекта и подключает только подходящие навыки.

## Пользовательские навыки

Свои навыки, которые должны применяться всегда и для любых задач (стиль ответов, личные правила, рабочие договоренности), кладите в каталог `user-skills` рядом с комплектом, по умолчанию `~/ai/user-skills/`:

```
~/ai/
├── agent-kit/          комплект, ставится установщиком
└── user-skills/        ваши навыки, в репозиторий комплекта не входят
    └── my-rules/
        └── SKILL.md    frontmatter с name (равен имени каталога) и description
```

- Установщик создает пустой `user-skills`, если его нет, и в режиме пользователя ставит ссылку на каждый подкаталог с `SKILL.md` в каталоги навыков агентов, так же как навыки комплекта. После добавления навыка перезапустите `install.py`.
- В общем каталоге навыков агента пользовательские навыки лежат вперемешку с навыками комплекта и ничем не отмечены. Поэтому установщик вписывает их имена в установленные `AGENTS.md` (строка `0. User Skills`) и `agent-kit-core.mdc`, и агент загружает их по имени. Навыки действуют и там, где ссылок нет: в режиме проекта и у агентов без механизма skills (они читают `<каталог>/<имя>/SKILL.md`).
- Список стоит между метками `<!-- kit:user-skills -->…<!-- /kit:user-skills -->`; в исходнике комплекта там `none installed`. Метки остаются в установленном файле, и при каждом запуске установщик переписывает значение между ними без вопроса о конфликте. Ваши правки в остальной части файла по-прежнему считаются конфликтом. Какие файлы так обрабатываются, задано в `rendered_files` в `kit.json`.
- В режиме проекта ссылки на `user-skills` не создаются, иначе ссылка на личный каталог попала бы в репозиторий проекта.
- Имя навыка не должно совпадать с навыком комплекта: при совпадении ставится навык комплекта, а установщик выводит предупреждение.
- Если комплект установлен с другим `--prefix`, каталог - `<prefix>/user-skills/`; установщик вписывает в `AGENTS.md` фактический путь.
- `--uninstall` удаляет и ссылки на пользовательские навыки; сами навыки остаются.
- `python3 install.py --list` выводит пользовательские навыки блоком `Tier 0` перед навыками комплекта.
- `python3 install.py --dry-run` показывает по каждому подкаталогу `user-skills` имя, путь и `description` из `SKILL.md`, а для пропускаемых - причину: нет `SKILL.md` или имя совпадает с навыком комплекта.

## Установка

Установщик работает в два этапа.

1. **Копирует комплект** в каталог установки: `<prefix>/agent-kit`, по умолчанию `~/ai/agent-kit`. Каталог задаётся ключом `--prefix`, переменной `AGENT_KIT_PREFIX` или ответом на вопрос при интерактивном запуске. Не копируются `.git`, сам `.gitignore` и всё, что в нём перечислено: правила игнорирования берутся из `.gitignore` комплекта.
2. **Создаёт симлинки** из каталогов, где агенты ищут навыки и инструкции, на файлы в каталоге установки. Обновление комплекта после этого сводится к повторному запуску `install.py`: ссылки уже указывают на новые файлы.

### Куда ставятся ссылки

Режим пользователя (по умолчанию) - навыки доступны во всех проектах:

| Агент | Навыки | Постоянные инструкции |
|---|---|---|
| Claude Code | `~/.claude/skills/<skill>` | `~/.claude/rules/agent-kit.md` → `AGENTS.md` |
| Codex и агенты, читающие `.agents/skills` | `~/.agents/skills/<skill>` | `~/.codex/AGENTS.md` → `AGENTS.md` |
| Cursor | `~/.cursor/skills/<skill>` | нет: глобальные правила Cursor задаются в его настройках |
| Gemini CLI | `~/.gemini/skills/<skill>` | `~/.gemini/GEMINI.md` → `AGENTS.md` |

Режим проекта (`--project DIR`) - ссылки создаются внутри проекта:

| Агент | Навыки | Постоянные инструкции |
|---|---|---|
| Claude Code | `.claude/skills/<skill>` | `.claude/rules/agent-kit.md` |
| Codex | `.agents/skills/<skill>` | `AGENTS.md` |
| Cursor | `.cursor/skills/<skill>` | `.cursor/rules/agent-kit-core.mdc` (always), `.cursor/rules/agent-kit-python.mdc` (для `*.py`) |
| Gemini CLI | `.gemini/skills/<skill>` | `GEMINI.md` |

Пути описаны в `kit.json` (раздел `agents`). Расположение каталогов навыков у агентов меняется от версии к версии: если ваш агент не видит навыки, сверьтесь с его документацией и поправьте путь в `kit.json`. Там же добавляется новый агент - кода менять не нужно.

Личный `~/.claude/CLAUDE.md` установщик не трогает: для Claude Code инструкции подключаются отдельным файлом в `~/.claude/rules/`.

### Выбор агентов и навыков

| Ключ | Значения | По умолчанию |
|---|---|---|
| `--agents` | `auto`, `all`, список через запятую | `auto`: агенты, у которых есть каталог настроек (`~/.claude`, `~/.codex`, `~/.cursor`, `~/.gemini`) |
| `--languages` | `auto`, `all`, `none`, список | в режиме пользователя - все языковые пакеты; в режиме проекта - определяются по файлам проекта |
| `--tech` | `auto`, `all`, `none`, список | в режиме пользователя - все технологии выбранных языков; в режиме проекта - найденные в зависимостях и файлах |
| `--no-instructions` | - | ставить только навыки, без `AGENTS.md` и правил |
| `--copy` | - | копировать вместо симлинков |

Engineering Core ставится всегда. В режиме пользователя ставятся все навыки, потому что агент сам выбирает нужные по описанию, а проекты бывают разные. В режиме проекта состав определяется по правилам `detect` из `kit.json`: имена пакетов в `pyproject.toml`, `requirements*.txt` и подобных файлах, наличие `Dockerfile`, `.github/workflows/*.yml`, `.gitlab-ci.yml` и так далее. Определение эвристическое; если оно ошиблось, задайте состав явно:

```bash
python3 install.py --project . --tech fastapi,sqlalchemy,postgresql,docker
```

Для командного репозитория используйте `--copy`: симлинк содержит абсолютный путь к вашему домашнему каталогу и у коллег работать не будет.

### Конфликты

Если по целевому пути уже что-то есть и оно отличается от версии комплекта, установщик останавливается и спрашивает:

```
Conflict: /Users/me/.claude/skills/fastapi
  existing: directory; it differs from the kit version /Users/me/ai/agent-kit/skills/tech/fastapi
  [o] overwrite   [b] back up, then install   [s] skip (keep existing)
  [d] show diff   [a] abort installation
  Add "!" to apply the choice to all remaining conflicts, e.g. "b!"
  Choice [s]:
```

| Ответ | Действие |
|---|---|
| `o` | Заменить существующее версией комплекта |
| `b` | Перенести существующее в бэкап и установить новое |
| `s` (Enter) | Оставить как есть, перейти к следующему |
| `d` | Показать unified diff (для каталогов - по всем файлам) и спросить снова |
| `a` | Прервать установку; уже сделанное остаётся, повторный запуск продолжит |
| `o!`, `b!`, `s!` | Применить ответ ко всем следующим конфликтам |

Правила:

- Ответ по умолчанию - «пропустить», как у `apt` при обновлении конфигов.
- Бэкапы складываются в `<prefix>/agent-kit-backups/<дата-время>/<полный путь>`, а не рядом с оригиналом. Иначе агент обнаружил бы сохранённый навык как второй экземпляр.
- Конфликтом не считаются: ссылка, уже указывающая на комплект (`ok`), и копия, побайтно совпадающая с версией комплекта (заменяется ссылкой, данные не теряются).
- Без терминала (CI, пайп) вопросы не задаются: существующее сохраняется, в отчёте оно помечено `skipped`. Политику можно задать явно: `--on-conflict overwrite|backup|skip|abort`.
- То же правило действует для файлов в каталоге установки. Если вы правили навык в `~/ai/agent-kit`, при обновлении установщик спросит о нём. Учтите, что `~/.codex/AGENTS.md` после установки - ссылка на `AGENTS.md` комплекта, и правка через неё меняет файл комплекта.

### Удаление

```bash
python3 install.py --uninstall                 # ссылки в домашнем каталоге
python3 install.py --uninstall --project DIR   # ссылки в проекте
```

Удаляются только симлинки, которые указывают внутрь каталога установки. Сам каталог, бэкапы и копии, сделанные с `--copy`, остаются на месте - их удаляйте вручную.

## Инженерная философия

`ub-mode` взят как основа инженерной системы, а не как ещё один навык: принципы записаны в `AGENTS.md`, развёрнуты в трёх навыках ядра, а Python-навыки на них ссылаются и конкретизируют.

**Attack the Premise.** После двух неудачных попыток исправить одну проблему агент прекращает править симптомы, выписывает предположения, на которых держится подход, и проверяет самое слабое. Пример из навыка: тесты конкурентной обработки задач не проходят после добавления блокировок - нужно проверить, кто владеет общим состоянием, а не добавлять третий lock.

**Test Behavior, Not Implementation.** Тест проверяет то, что наблюдает пользователь модуля, а ожидаемые значения выводятся из требования, а не копируются из вывода кода. Иначе агент пишет тесты, которые подтверждают его собственные ошибки.

**Subtract Before You Add.** Прежде чем добавить класс, абстракцию, настройку или зависимость, агент проверяет, не решается ли задача удалением или упрощением существующего.

### Что изменено относительно ub-mode

| Принцип ub-mode | В этом комплекте |
|---|---|
| Всегда сначала TDD | TDD по умолчанию для изменений поведения и исправления ошибок; без искусственных тестов для тривиальных правок (переименования, комментарии, конфигурация) |
| CRAP < 10 для каждой функции | Целевой показатель; исключения допускаются и обосновываются; функции не дробятся ради метрики |
| Устранять дублирование от 0.8 | Сходство - повод посмотреть; объединять только знание, которое обязано меняться вместе |
| Журнал каждого действия | Записываются существенные решения и проверки |
| Worktree Cleanup | Пользовательская работа не удаляется автоматически; агент перечисляет, что можно убрать, и спрашивает |
| Commit and Push | Commit только по запросу; push, merge, тег, релиз - только с явного разрешения на конкретное действие; никогда в main по своей инициативе |

Дополнительно из направления UB Python (современная типизация, Pydantic v2, валидация на границах, правила обработки ошибок) собран навык `python-development`.

## Инструменты качества

Ни один инструмент не обязателен. Агент использует только то, что уже установлено в проекте, не устанавливает ничего сам и в отчёте указывает пропущенные проверки. Сначала посмотрите, что есть:

```bash
uv run python ~/ai/agent-kit/tools/check_tools.py
```

Скрипт нужно запускать интерпретатором проекта, чтобы он увидел инструменты из окружения проекта. Он ничего не устанавливает.

Метрики - индикаторы, а не доказательство качества. CRAP, процент покрытия и процент дублирования показывают, куда посмотреть.

### Рекомендуемый состав

| Проверка | Инструмент | Когда |
|---|---|---|
| Тесты и покрытие | pytest, pytest-cov | Базовая проверка, всегда |
| Стиль и статический анализ | Ruff | Всегда |
| Типы | mypy или Pyright (один из двух) | Всегда |
| Сложность | radon | Дополнительно, для новой и изменённой логики |
| CRAP | `tools/crap.py` (radon + coverage) | Для новой и изменённой логики |
| Мутационное тестирование | mutmut | Для критичной бизнес-логики |
| Дублирование | pylint `duplicate-code` | По необходимости |
| Зависимости | pip-audit | Перед релизом, в CI |

### Установка в проект

С uv инструменты добавляются в dev-группу и не попадают в зависимости приложения:

```bash
uv add --dev pytest pytest-cov ruff mypy
```

```bash
uv add --dev radon mutmut pip-audit
```

Без uv - в виртуальное окружение проекта:

```bash
python -m pip install pytest pytest-cov ruff mypy radon mutmut pip-audit
```

### Подключение в pyproject.toml

Добавляйте только секции для установленных инструментов; `my_package` и `src/` замените своими.

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers"

[tool.coverage.run]
source = ["my_package"]
branch = true

[tool.coverage.report]
show_missing = true
skip_covered = true

[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "S", "C90"]

[tool.ruff.lint.mccabe]
max-complexity = 10

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]

[tool.mypy]
strict = true
files = ["src", "tests"]

[tool.mutmut]
paths_to_mutate = ["src/my_package/"]
tests_dir = ["tests/"]
```

Имена ключей `[tool.mutmut]` зависят от версии mutmut - сверьтесь с его документацией. Для Pyright вместо `[tool.mypy]` используется `[tool.pyright]` с `typeCheckingMode = "strict"`.

### Команды

```bash
uv run pytest --cov --cov-report=term-missing --cov-report=json
```

```bash
uv run ruff check . && uv run ruff format --check .
```

```bash
uv run mypy
```

```bash
uv run radon cc -s -n C src
```

```bash
uv run python ~/ai/agent-kit/tools/crap.py --coverage coverage.json src
```

```bash
uv run mutmut run
```

`crap.py` считает `CRAP = complexity² × (1 − coverage)³ + complexity` для каждой функции по отчёту `coverage.json` и данным radon и печатает функции с наибольшим значением. Код возврата всегда 0, если не задан `--strict`; цель по умолчанию 10 (`--threshold`). Скрипту нужен установленный radon либо сохранённый отчёт `radon cc -j` (`--radon FILE`).

Чтобы агент использовал именно эти команды, оформите их в проекте - в `Makefile`, `justfile`, `noxfile.py` или в разделе README. Навык `ub-quality-gates` предписывает сначала искать команды проекта и только потом применять типовые.

### Проверки уровня интеграции

Для FastAPI, Django, SQLAlchemy и PostgreSQL метрик кода недостаточно. В соответствующих навыках есть раздел Quality gate: тесты на реальной СУБД, а не на SQLite; `alembic upgrade head` с пустой базы; `makemigrations --check`; контроль изменений OpenAPI-схемы; проверка количества запросов.

## Язык текста в коде

Русский язык допускается только в комментариях, docstrings и документации. Весь остальной текст всегда пишется на английском, независимо от языка комментариев в файле: сообщения в логах, тексты исключений, ответы и ошибки API, сообщения валидации, вывод и справка CLI, идентификаторы, имена тестов, ключи конфигурации, сообщения коммитов и названия веток.

Для комментариев и документации правило записано в `AGENTS.md` и `python-documentation`:

- в файле английские комментарии - новые на английском;
- русские - новые на русском;
- оба языка примерно поровну - предпочтителен русский;
- комментариев нет - ориентир на соседние файлы, при отсутствии конвенции - русский;
- существующие комментарии массово не переводятся;
- буква «ё» не используется;
- длинное тире `—` не используется, вместо него ставится дефис `-`;
- в конце предложения или абзаца, за которым нет текста или идет пустая строка, точка не ставится.

## Как добавить язык или технологию

Комплект состоит из пакетов (`packs` в `kit.json`) трёх видов: `core`, `language`, `technology`. Ядро подключается всегда, языковые пакеты - по языку проекта, технологии - по зависимостям и файлам. Сейчас есть один языковой пакет, `python`.

### Новый язык

1. Создайте каталог `skills/<язык>/` и в нём навыки с префиксом языка, например `skills/go/go-development/SKILL.md`, `skills/go/go-testing/SKILL.md`. Имена навыков должны быть уникальны во всём комплекте: агенты хранят их в одном плоском каталоге.
2. Опишите пакет в `kit.json`:

   ```json
   "go": {
     "tier": 2,
     "kind": "language",
     "path": "skills/go",
     "detect": {"files": ["go.mod", "*.go"]},
     "skills": {
       "go-development": {},
       "go-testing": {}
     }
   }
   ```

3. Добавьте в `dependency_files` файлы зависимостей языка (`go.mod`), чтобы работало определение технологий по именам пакетов.
4. Добавьте строку пакета в таблицу уровней в `AGENTS.md`, чтобы агент знал о маршрутизации; для Cursor - файл `adapters/cursor/rules/agent-kit-go.mdc` по образцу Python-правила и запись о нём в `agents.cursor.project.files`.
5. Запустите `python3 tools/validate_kit.py` и `python3 install.py --dry-run`.

Навыки ядра не зависят от языка и переписывать их не нужно. Таблицу инструментов для нового языка разместите в его навыке тестирования, а не в `ub-quality-gates`.

### Новая технология

1. Создайте `skills/tech/<имя>/SKILL.md`.
2. Добавьте запись в пакет `tech`:

   ```json
   "celery": {
     "languages": ["python"],
     "detect": {"deps": ["celery"]}
   }
   ```

| Поле | Смысл |
|---|---|
| `languages` | Навык подключается только вместе с этими языковыми пакетами. Не указано - технология не зависит от языка (`postgresql`, `docker`, `ci-cd`) |
| `detect.deps` | Имена пакетов; ищутся как отдельные слова в файлах из `dependency_files` |
| `detect.files` | Glob-шаблоны относительно корня проекта |
| `detect.content` | Подстроки в тех же файлах зависимостей (например, `postgres` в `compose.yaml`) |

Достаточно совпадения по любому правилу.

### Требования к SKILL.md

Они следуют рекомендациям Anthropic по написанию skills; тот же формат читают Codex, Cursor и Gemini CLI.

- Frontmatter с двумя полями: `name` (совпадает с именем каталога; строчные буквы, цифры, дефисы) и `description` (до 1024 символов).
- `description` написано в третьем лице и отвечает на два вопроса: что делает навык и когда его применять. По нему агент решает, загружать ли навык. Для технологий условие указывайте явно: «Use only when the project uses …».
- Тело до 500 строк. Пишите только то, чего модель не знает сама или в чём ошибается; объёмные справочные материалы выносите в отдельные файлы рядом и ссылайтесь на них.
- Конкретные правила и проверяемые критерии вместо общих пожеланий; в конце - что должно быть проверено (Quality gate) или что должно быть в отчёте.
- Текст на английском.

## Разработка комплекта

```bash
python3 tools/validate_kit.py
```

Валидатор проверяет: у каждого навыка из `kit.json` есть `SKILL.md` с корректным frontmatter; в каталогах нет навыков, не описанных в манифесте; имена уникальны; файлы, на которые ссылаются агенты, существуют.

Установщик удобно проверять на временном каталоге, не затрагивая настоящие настройки:

```bash
python3 install.py --home /tmp/kit-test --agents all --dry-run
```

Скрытый ключ `--home` подменяет домашний каталог.

Тесты установщика используют только стандартную библиотеку:

```bash
python3 -m unittest discover -s tests
```

## Источники и ограничения

- [ub-mode](https://github.com/unclebob/ub-mode) Роберта Мартина - основа ядра.
- [Uncle Bob Skills Catalog](https://robert-hoffmann.github.io/uncle-bob/skills) - направления UB Quality, UB Workflow, UB Python.
- Рекомендации Anthropic по Agent Skills, формат `AGENTS.md`, документация по skills в Codex, Cursor и Gemini CLI.

Тексты навыков написаны заново и не являются копией этих материалов. Принципы `ub-mode` изложены по их описанию в постановке задачи: дословная сверка с исходными репозиториями не проводилась, а поддержка Python в companion-инструментах не проверялась. Пути каталогов навыков у агентов указаны по состоянию на момент написания и вынесены в `kit.json`, чтобы их можно было поправить без изменения кода.
